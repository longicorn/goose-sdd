# 要求仕様書: `goose-sdd --implement` コマンド

## 概要
`goose-sdd --implement` 機能は、小中規模かつ高速な開発（Direct / Vibe Pattern）に特化した、最低限のドキュメントで仕様駆動開発（SDD）を行うための機能です。

## 背景・目的
既存の `system` レイヤー（全体設計）および `feature` レイヤー（機能開発）は、大規模開発向けの Macro/Micro パターンとしては優れていますが、小規模〜中規模の開発には重厚長大であり、手軽に使いづらいという課題がありました。
一方で、AIエージェントへのプロンプトのみで完結させ、全くドキュメントを残さない「Vibe Coding」では、後からの保守や改修が困難になります。

本機能（`implement`）は、「Vibe Coding 以上の最低限のドキュメントは残しつつ、小中規模の高速開発を行いたい」というニーズに応え、軽量かつ迅速な仕様駆動開発サイクルを提供することを目的とします。

## ユースケース / ユーザーストーリー
- **小規模だが長く使うツールの開発**
  - ユーザーは、特定の目的を持った小さなユーティリティツールを開発したいと考えている。
  - 完全なドキュメントレス（Vibe Coding）では将来の保守が不安なため、`goose-sdd --implement init` を実行し、必要最低限の要件（`requirement`）のみを定義する。
  - その後、すぐに `goose-sdd --implement code` を実行して実装を完了させる。設計（`approach`）や事前テスト（`test`）はツールの規模に応じてスキップし、素早くリリースする。

## 機能要件
すでに `./recipes/implement/` 配下のレシピとして実装済みであり、以下のCLIコマンドおよび開発サイクルをサポートします。

1. **初期化 (`init`)**: `docs/sdd/implement/` ディレクトリの作成および初期テンプレートの生成。
2. **要件定義 (`requirement`)**: 最低限の要求仕様の作成および更新。
3. **アプローチ検討 (`approach`) [スキップ可能]**: 実装方法や設計方針の検討・文書化。
4. **テスト作成 (`test`) [スキップ可能]**: 要件やアプローチに基づいたテストコードの生成。
5. **コード実装 (`code`)**: 仕様に基づいたソースコードの実装・修正。
6. **レビュー (`review`) [スキップ可能]**: 実装されたコードとドキュメントの整合性チェックおよびレビュー。

## 非機能要件
1. **高速性と軽量性**:
   - `system` や `feature` レイヤーのような多数のドキュメントを要求せず、開発のオーバーヘッドを最小限に抑えること。
2. **柔軟性**:
   - `requirement` と `code` 以外のステップ（`approach`, `test`, `review`）は、プロジェクトやタスクの性質に応じて開発者が任意にスキップできること。
3. **保守性の担保**:
   - 小規模・高速開発であっても、最低限の要件仕様書が残ることで、長期間利用するソフトウェアの保守性を維持できること。
