# 要求仕様書: Tool (goose-sdd --tool)

## 概要
`goose-sdd --tool` コマンドは、`goose-sdd` においてユーザーの開発作業を支援する便利なユーティリティ機能群を提供するサブコマンドです。本コマンドは、ユーザーがプロジェクトの仕様や設計を深く理解し、スムーズに開発を進められるようにサポートすることを目的としています。

## 背景・目的
`goose-sdd` を使用してシステムや機能の設計・実装を進めるにあたり、プロジェクト全体の仕様や既存のドキュメント（SDD）の内容を正確に把握することは不可欠です。しかし、ドキュメントの量が増えるにつれて、必要な情報を探し出したり、全体像を理解したりすることが困難になる場合があります。
本ツール機能は、AIエージェントが既存のドキュメントを読み込んでコンテキストとして保持し、対話形式でユーザーの疑問に答えることで、プロジェクトへの理解を深め、開発効率を向上させることを目的としています。

## ユースケース / ユーザーストーリー
### ユースケース1: プロジェクト仕様の相談 (`goose-sdd --tool ask`)
*   **アクター**: 開発者（ユーザー）
*   **事前条件**: `docs/sdd/` 以下にプロジェクトの仕様ドキュメント（コアドキュメントおよび機能ごとのドキュメント）が存在すること。
*   **メインフロー**:
    1.  ユーザーがターミナルで `goose-sdd --tool ask` を実行する。
    2.  ツールは `docs/sdd/` 以下の指定されたドキュメント群（コアドキュメントおよび `sdd.yaml` で `load_contexts.consult: true` が設定された機能ドキュメント）を読み込み、プロジェクトのコンテキストを構築する。
    3.  ツールは起動時の表示を最小限に抑え、不要な説明や冗長な準備完了メッセージを出さずに対話を開始できる。
    4.  ユーザーはプロジェクトに関する質問や相談（例：「新しい機能を追加したいが影響範囲は？」「この機能のビジネス要件を要約して」など）を入力する。
    5.  ツールは読み込んだコンテキストに基づき、シニアアーキテクトの視点から的確な回答やアドバイスを提供する。
    6.  ユーザーは疑問が解消されるまで対話を継続できる。

## 機能要件
1.  **ドキュメント探索・読み込み機能**: `docs/sdd/` ディレクトリ直下のコアドキュメント、および各機能ディレクトリを再帰的に探索し、条件に合致するドキュメントを動的に読み込む機能。
2.  **対話型コンサルテーション機能 (`ask` コマンド)**:
    *   読み込んだドキュメント情報をコンテキストとして保持し、ユーザーからの自然言語での質問に応答する機能。
    *   プロジェクトの全体像、アーキテクチャ、ビジネス要件、開発ルールなどに関する多角的な分析と回答を提供する機能。
3.  **拡張可能なツールコマンド体系**: `goose-sdd --tool <subcommand>` の形式で各種ツールを起動でき、今後ツール（レシピ）が増えた場合にも対応できる仕組み。

## 非機能要件
1.  **安全性（セーフティ）**:
    *   本ツール（特に `ask` コマンド）は原則として読み取り専用モードで動作すること。
    *   ユーザーからの明示的な指示がない限り、ファイルの作成、変更、およびリソースの削除などの破壊的な操作や危険な操作を一切行わないこと。
2.  **拡張性**: 将来的に `ask` 以外の新しいツール用レシピを `./recipes/tool/` に追加することで、容易に機能を拡張できること。
